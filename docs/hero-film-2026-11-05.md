# Stocklumo — Signal study, 5 November 2026

## Direction and storyboard

Three concepts were compared: a miniature research terminal (clear but too close to a dashboard slideshow), a camera flight through market geometry (expressive but crop/performance risks), and a paired signal ribbon (original logo connection, coherent visual language and an analytically periodic loop). The signal ribbon was selected for the existing split composition. This supersedes the homepage WebGL entry, not the rest of the product design.

| Time | Composition |
| --- | --- |
| 0–1.2 s | Paired satin signal surfaces already in motion, with a small camera breath. |
| 1.2–2.8 s | Two normalized illustrative paths emerge through the ribbon. |
| 2.8–5.1 s | The 100.00 → 102.50 example resolves to `(102.50 − 100.00) / 100.00 × 100 = +2.50%`. |
| 5.1–7.8 s | The chart recedes as the actual brand SVG emerges from the paired surfaces. |
| 7.8–10.8 s | Recognizable, unchanged logo front face; a restrained clarity caption. |
| 10.8–13.8 s | Logo yields back to the moving signal surfaces. |
| 13.8–15.0 s | Opening state and velocity reconnect through periodic geometry. |

This is authored 2.5D Canvas motion, not generated footage or a recording of live Finnhub data. The original logo SVG is loaded directly and drawn at its original aspect ratio and colors. Curves and mathematics are deliberately illustrative and labeled in every frame. No API calls are made by production rendering or video playback. No paid template, generated replacement logo, random particles, trading imagery or stock footage was used.

## Deliverables and reproduction

`MarketDesk/wwwroot/media/hero/` contains dark/light H.264 MP4, VP9 WebM and JPEG posters. Both masters are 1920×1080, exactly 15.0 seconds, 450 frames at 30 fps, without audio. MP4 uses YUV420p and fast-start metadata. MP4 sizes: dark 1,028,625 bytes; light 959,638 bytes. WebM sizes: dark 734,649 bytes; light 601,673 bytes. Posters are approximately 44 KB each. Lossy compression introduces small color differences; original SVG source values remain unchanged.

Source: `frontend/hero-film.html`. Pipeline: `node tools/render-hero-film.cjs <FFmpeg executable path>`. It requires the existing Playwright/Chromium installation and FFmpeg with libx264/libvpx-vp9. FFmpeg was obtained as an ignored, build-only `imageio-ffmpeg` tool under `output/video-tools`; no npm/application dependency was added. Regenerate only while builds/servers are stopped, because .NET fingerprints public assets and cannot read a file while FFmpeg is replacing it on Windows.

Each variant is rendered frame by frame and streamed into FFmpeg, then completely decoded to check integrity. The renderer compares the PNG at analytic time 15.0 against time 0 byte for byte; both variants passed. The final encoded frame-to-first mean channel differences (0–255 scale) were 0.572 dark / 0.491 light, compared with 0.525 / 0.438 between the preceding two frames: the seam is comparable to ordinary movement, with no blank/fade-to-black reset. Exact encoded endpoint equality is not claimed.

## Integration and behavior

- Existing headline, search, actions, 62/38 desktop split, hero sizing and compact contained stage are preserved. The animated asset is pointer-transparent, decorative and aria-hidden. Real quotes remain in the actual application.
- `_SiteHead.cshtml` loads `hero-video.js` only on the homepage. It no longer imports the 732 KB Three.js/GSAP hero bundle; historical sources and build pipeline remain for rollback.
- `Index.cshtml` supplies native muted/autoplay/loop/playsinline video with preload none and no initial source. Theme-specific posters render without JavaScript. The loader attaches one supported source after load/idle and only when visible.
- Theme changes release the old source and select the correct variant. Reduced motion / Save-Data never attach video sources. Offscreen, hidden-document and pagehide states pause playback. Existing global motion preference and the visible hero pause/resume button share the same control owner. A late playing event checks pause/reduced/visibility state again.
- Blocked autoplay offers an explicit Play action. Failed media leaves the poster and search usable. No looping retry is performed on a failed source.
- `Program.cs` adds only `media-src 'self'` to the existing CSP; the initial browser check found video was blocked by `default-src 'none'`. No external source or broad relaxation was introduced.

These cover all five originally failed cases and the final playback/palette/reduced-motion/viewport/cancellation behavior on all three browser profiles. This is an integration-order observation, not a cold-network benchmark, field Core Web Vital, or production speed guarantee. Raw resource timings are retained.
- Browser evidence and encoding reports: `output/hero-film/`; integrated captures in `output/playwright/` and Playwright test outputs. Browser emulation is not physical-device battery, codec or field performance evidence. No universal sub-two-second load guarantee is made.

The video payload replaces runtime WebGL work but is not claimed to reduce transfer versus every prior hero state. Reduced-motion/Save-Data and non-home routes avoid the video entirely. Production deployment has not occurred.
